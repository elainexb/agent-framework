# 历史、来源与恢复

仅在核查旧决定、批准、失败、许可或恢复时读取。日常任务从[现行入口](../CODEX_START_HERE.md)取得当前依据。

## 可共享的迁移定位

[迁移清单](../../review/skill-verification-20261027/evidence/application-20261027/migration-map.json)是统一前管理文档的追溯映射，记录旧路径、当前所有者、归档路径、原件SHA256与保留理由。它不定义当前要求，也不表示清单中的原件都随Git提供。

## 只在原工作区保留的材料

统一前101份管理原文保存在本机`history/legacy/`，字节未改。原始功能证据在`features/observability_oss_audit/evidence/`，评分实验在`.scratch/agent-workbench/experiments/lc-lg-mlflow/evidence/`；治理原始会话和迁移回执在工作区`review/`的相应试验目录。这些材料含本机环境或过程上下文，未纳入此次Git基线；克隆仓库不会获得它们。本文用路径说明其本机位置，不把缺失原件伪装成可用的仓库链接。

## 如何追溯与恢复

1. 先从现行正文取得当前结论，仅在确需原始批准、失败现场或恢复时按迁移清单定位。
2. 本机有原件时，核对清单中的SHA256；历史原文的相对引用仍是当时路径，按清单解析旧位置。
3. 只有Git副本时，原始输出与批准原件的独立复核保持不可用；需要时向项目维护者取得经过审查的相关原件，不由迁移哈希反推批准或成功。
4. 恢复前核对原件身份及当前文件变化，避免覆盖后续有效修改；运行与实现仍以现行源码为准。需要重放历史实验时，读取[重放前提](../docs/current/使用与排错.md#历史实验重放前提)，核对当前环境与权限。
