# 持久设计决定

用途：新任务或架构修改时继承已确认理由，识别必须重新评估的边界。本文拥有选择与取舍；实际代码和当前执行状态分别查源码及[当前工作](当前工作.md)。

## 第一代运行底座

原ADR-001：starter阶段采用LangChain create_agent与LangGraph作为共享Agent循环，以教学和复用成熟机制为理由。项目负责业务规则、应用装配和必要接线，不为不同Agent复制运行循环。

当多轮规划、子任务隔离、文件/上下文管理确实超过现有装配时，重新研究当前公开组件、适用性、许可、本机兼容和迁移成本；Deep Agents或自定义工作流仍须实际需求与验证，不能当直接替换结论。

## 业务与共享底座分离

原ADR-002：只服务某业务的规则放业务资产；跨多个Agent确有共性的机制才进入foundation。工具接口与确定性业务逻辑分开，使计算与权限等规则能独立检查、复用，而不随模型表达改变。

具体修改路线与例子由[架构与修改](架构与修改.md)维护，不在此复制逐文件清单。

## Git与任务状态的职责

ADR-004：用户已确认使用Git管理源码、配置、指令、方法、需求/设计、案例及可共享记录的版本，新功能在feature branch开发。Git避免另建一套文件版本库；分支/提交本身不表示用户接受、运行启用或模型验证。

开发任务仍须记录目标、步骤、批准、缺项、部分成果和证据。接续时核对分支/提交、未提交与未跟踪变化；只给commit会遗漏未保存进历史的工作。

模型权重、大型/私有数据、密钥和本机数据库不因使用Git就自动跟踪、上传或发布。Trace/评分/反馈有独立运行记录职责；资源使用引用和适用身份关联。

同一工作目录切分支会改变工作台读到的文件。如果未来需要稳定版与开发版同时使用，可研究两个Git worktree及各自环境/资源绑定；worktree不构成沙箱，也不自动隔离数据库或模型。具体工程状态、准备范围与后置安排只在[当前工作](当前工作.md)维护。

## 开源复用的约束顺序

通用能力先核对已有代码和成熟公开组件，只为真实缺口设计必要适配或业务代码。具体费用和许可约束以[产品要求](产品需求.md#费用证据数据与变更约束)为准，不能把“本地可启动”或“免费额度”当作符合采用条件。

早期ADR-003与OPEN_SOURCE_REUSE中的“优先Phoenix”只是旧候选，未成为当前选型。P1有限实验接受也不等于最终选用MLflow或应用集成已批准。以后实际选型时重新查目标版本与本地关键路径，不沿用旧推荐排序。

## 决定怎样维护

仅记录影响未来维护的实质决定：问题/约束、选项与代价、选择及理由、批准依据、适用范围和重审条件。新决定取代旧决定时，现行章节呈现有效结论，历史原件保留原身份；候选与已确认分别标记。当前任务的进度不复制到本文件。
