# 项目术语

用途：新工作、设计和解释中避免混淆对象。这里只定义含义，需求、状态和实现分别由其所有者维护。

**Agent开发工具**：帮助用户搭建、配置、验证、交付和持续修改不同业务Agent的开发系统。
_Avoid_: 用“某个业务Agent”或“Skill生成器”指代整个开发工具。

**开发助手**：代表用户执行Agent开发工作的助手；当前使用Codex，也包括用户希望接入的本机Claude Code等宿主。
_Avoid_: 不加说明地把开发助手称为业务Agent。

**业务Agent**：由开发工具搭建、面向具体任务供用户使用的助手，例如数据分析助手或资料问答助手。
_Avoid_: 用“开发助手”指代被搭建的业务Agent。

**共同开发方法**：不同开发助手搭建和修改业务Agent时共同遵循的需求、设计、生成、配置、检查与交付方法。
_Avoid_: 把某个宿主的入口或一次聊天提示词当成共同方法本身。

**开发配方**：共同开发方法中，针对某类产物说明如何复用、创建、修改及验证的方法。
_Avoid_: 把开发配方与业务Skill混称为同一个Skill。

**业务Skill**：业务Agent在执行任务时按需使用的业务方法及相关资源。
_Avoid_: 用业务Skill指代生成它的开发配方。

**产物约定**：一类产物在内容含义、输入输出、依赖、引用和失败表达上需满足的共同约定。
_Avoid_: 把统一约定理解为所有类型产物必须采用同一种格式。

**开发任务**：一次有明确目标和批准范围的业务Agent新建或修改工作。
_Avoid_: 用一次业务Agent运行指代开发任务。

**工作台**：用户发现、选择、使用业务Agent并查看状态、结果和反馈的共同界面；具体可用能力以实际接通状态为准。
_Avoid_: 把工作台界面本身当成Agent执行或独立评分逻辑。

**开发接力**：一个开发助手留下任务、产物与证据，另一个开发助手核对这些记录后继续同一开发任务。
_Avoid_: 把开发接力等同于业务Agent对话恢复或运行模型切换。

## 运行与验证称呼

- **Model（模型）**：接收输入、进行语言推理并可能提出工具调用；提出调用本身不等于工具已执行。
- **Runtime / Agent Loop（运行时）**：执行模型与工具之间的控制循环。实际装配入口见[源码](../../foundation/builder.py)。
- **Application Harness（应用级控制与装配）**：围绕模型/工具管理输入、状态、权限、预算、失败和验证的机制；具体边界见[架构与修改](架构与修改.md)。
- **Tool（工具）**：有明确参数、结果和副作用边界的可执行操作。
- **Workflow（工作流）**：按明确次序和分支执行的流程；是否让模型动态决定下一步按任务判断。
- **MCP**：工具/资源等交互协议；支持协议不等于已有业务权限或完整Agent循环。
- **Ontology（领域语义）**：实体、标识、指标含义与关系的约定；不预设必须采用图数据库。
- **技术验证／用户接受**：前者是实际检查的结果，后者是用户对对应交付的明确接受；二者分别记录。
