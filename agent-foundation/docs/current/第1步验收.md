# 第1步：构建Agent的验收

用途：review、实现和检查构建步骤时使用。本文拥有T1—T5的完整输入、操作、预期、通过/失败条件及验证方法；批准、执行状态和票依赖由[当前工作](当前工作.md)维护。案例依据[产品需求](产品需求.md)，具体构建方法见[开发方法](开发方法.md)。

采用项目已有合成支持手册作为技术素材；案例不是正式业务立项，也不调用业务模型。准备坏输入时使用隔离副本，不损坏正常Agent、原始资料或模板。T1—T5是验收场景，不要求机械对应五个自动测试。

### T1 — 描述一个任务，确实构建出对应Agent

- **Input：** 对Codex说：“使用项目现有的合成支持手册，创建名为handbook_trial的资料问答Agent；先查资料，回答引用资料/章节，没有依据时明确说明。” 测试目标目录预先不存在；资料使用现有手册，其中Severity章节明确P0需立即升级给incident commander。
- **Action：** Codex读取项目共同方法，说明复用及必要组成，按获准任务生成/补齐产物，再调用现有inspect检查。不是只执行一次scaffold就宣布完成。
- **Expected output：** Agent目录中有匹配名称/用途的配置、针对资料问答的指令、必要检索工具/服务及有效资料路径或引用、至少一个有独立来源的测试案例；任务记录列实际文件、检查和未验证项。不得输出一个虚构的模型回答冒充运行证据。
- **PASS criteria：** 配置名称与目录一致；配置注册的工具能在该Agent源码中找到；指令包含“先查资料、引用章节、证据不足说明不足”三个要求；检索业务内容明确使用给定资料或复用已有真实检索服务，不能是TODO/固定成功占位；案例输入和预期来自实际手册；configuration/tools两项PASS，模板未完成不能当成功，模型/运行继续未验证。人核对任务内容和引用，不能只看退出0或文件数。
- **FAIL例子：** 只改Agent名称，留下默认任务/占位服务；资料指向不存在路径；报告“已经能回答问题”但没有运行。
- **验证方式：** 实际让Codex按项目共同方法处理这条任务，保存读取的材料、生成/复用的文件及inspect报告；自动静态检查配置/工具引用，人工逐项核对任务指令、检索内容和手册来源。配方文件存在、文件数或validator通过均不能替代真实构建记录。

### T2 — 构建出来的同一Agent能在现有目录页找到

- **Input：** T1中完整产物的独立副本及其本次inspect报告。
- **Action：** 实际打开现有目录页，点重新载入，选择handbook_trial。
- **Expected output：** 下拉列表中出现handbook_trial，页面显示其任务用途、同一模型声明、配置/工具检查结果及源码身份；明确网页试跑尚未接通。
- **PASS criteria：** Agent名称、配置声明、configuration/tools状态和source_version与同份文件的CLI报告一致；该目录页未提供/未声称真实模型运行成功。浏览器中的实际显示有记录，不能仅用页面函数单测代替。
- **FAIL例子：** 文件已生成但页面找不到；页面读旧配置或另一目录；把“配置检查通过”显示成“Agent运行成功”。
- **验证方式：** 真实浏览器操作；保留刷新并选择同一Agent后的页面记录，与同份产物的CLI报告逐项比对。页面函数单测只作回归，不能替代此项。

### T3 — 工具引用写错时，检查会指出错误

- **Input：** 完整Agent的临时副本；把一个工具注册引用改成不存在的missing_tool，保留有效YAML格式，其余内容不变。
- **Action：** 执行该副本的inspect检查。
- **Expected output：** 命令退出码2；工具检查为FAIL，说明指出missing_tool不存在；没有连接模型或导入/执行业务工具。
- **PASS criteria：** 检查确实拒绝坏引用，指出缺哪个工具；没有“构建交付通过/可运行”的结论；原正常Agent未修改。
- **FAIL例子：** 输出成功并忽略missing_tool；只报“发生错误”而不说明缺项；为了检查引用而实际调用模型或工具。
- **验证方式：** 通过现有inspect公开CLI入口作自动回归，保存退出码、报告及隔离副本差异；由检查路径核对没有连接模型或导入/执行业务工具。

### T4 — 同名Agent已存在时，不覆盖已有文件

- **Input：** 隔离目录中已有handbook_trial，指令中放入可核对的文字“保留这段原始说明”，并保存全部原文件的内容基线。
- **Action：** 再执行现有scaffold创建同名Agent。
- **Expected output：** 命令退出码2，明确目标已存在/拒绝覆盖，原目录及全部已有文件保留。
- **PASS criteria：** 全部原文件内容与基线一致，包括那段说明；没有先删除再创建，没有绕过拒绝改另一个名称冒充同一任务完成。文件内容比较用于核对未变，不用于证明业务正确。
- **FAIL例子：** 命令虽然报错，但原指令/工具已被覆盖；助手删除原目录后重新scaffold。
- **验证方式：** 通过现有scaffold公开CLI入口作自动回归，保留拒绝信息和退出码；独立比较操作前后的全部已有文件内容与目录清单，包括哨兵说明。

### T5 — 生成中途报错后，保留成果，再核对后继续

- **Input：** 一个全新测试目标和隔离模板副本；在副本中放入不能按UTF-8读取的文本文件，使文件复制完成后、模板内容处理时产生一个可重复的真实文件错误。只损坏这个测试输入，不修改项目模板。
- **Action：** 先执行生成并观察失败；保存失败后的文件/错误记录。然后让Codex“核对已有文件及失败原因，修正本次测试输入并继续补齐这个Agent”，不删除整个目标或重新覆盖。
- **Expected output：** 首次生成返回不成功，明确失败和未完成；已经复制/生成的文件保留，正常Agent不受影响；续接后缺失/不完整部分补齐，再inspect，最后在目录页核对同一目标。没有新增自动resume服务或虚构resume命令。
- **PASS criteria：** 失败时目标和已有成果没有被自动删除，记录足以定位失败/缺项且不标完成；助手续接前实际读取/核对成果，修正属于本任务的问题并增量完成；原有正常Agent不变；最终达到T1/T2的构建/目录条件，模型仍未验证。
- **FAIL例子：** 失败后整目录被清理；不看已有文件就从头覆盖；只把状态改成“完成”而引用仍错。
- **验证方式：** 两段分别取证：自动回归检查受控文件错误后的不成功结果、错误信息和成果保留；再真实让Codex读取、核对并增量补齐，同一目标重做inspect及真实目录核对。续接是助手操作记录，不是模拟回复或新增resume命令。

### 执行与证据规则

- 预期来自已确认需求和实际材料。T1案例可用手册Severity中的P0问题，独立预期依据是“立即升级给incident commander并引用来源”；本步核对案例/检索产物，不能用虚构模型回答当运行证据。
- 适合自动化的行为优先走现有CLI公开入口，准备临时文件输入并观察报告/产物，不以内部函数调用次数或复制实现算法作正确性依据。真实浏览器显示和真实助手续接分别保留操作记录。
- 每个检查记录输入身份、实际命令/操作、输出/差异或截图及PASS/FAIL/UNKNOWN/N/A。缺证据的结果为UNKNOWN；未执行统一记NOT_RUN，不能因别的检查通过而抵消失败。
- 实施阶段对新增/修复行为逐条“真实red→最小实现→同一检查green”；不是先写完全部自动测试。已有不变路径复用相应回归，不为文案或Git命令制造red。T5需要暴露“成果未保留”的真实缺口，预期文件错误本身不是缺口。
- 后续行为交付时固定同一候选，完成适用检查及真实目录验证，再做独立Standards/Spec review，之后请用户接受。技术结果、独立review、用户接受分开记录。
