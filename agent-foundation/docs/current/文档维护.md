# 本项目文档维护约定

用途：创建、修改、合并、退役文档及交接时使用。本文件只维护本项目资料的方法；具体需求、任务、验收、决定各有所有者，见[主索引](../../CODEX_START_HERE.md)。这是本项目当前维护约定；全局规则采用由外层任务另行管理。

## 写入前确定必要性

对新文档和拟保留内容说明：谁在什么后续任务读取，支持什么动作/决定，代码/配置/schema或已有正文能否方便提供同一信息，额外价值是什么。“以后也许有用”不构成保留理由。

实现字段、默认值、函数签名、目录树、依赖版本和工具清单直接定位真实来源；文档保存必要需求、语义、理由、理解路线、操作顺序、独立预期和实际证据。代码是实现事实的来源，不因此替代定义应有行为的规格。

## 先归属，再组织内容

主索引只拥有主题、读取条件、独特职责和正文位置。每份受管MD须属于现行索引、原生资产清单或历史清单；当前要求不能只藏在历史里。原生运行时/Skill/许可文件保留各自消费者和格式，索引不复制其正文。

文档按对象采用固定章节：任务写目标/依赖/状态/成果/阻断/下一步；要求写范围/约束/例外/验收依据；验收写输入/操作/预期/失败/验证；决定写理由/取舍/批准/重审；操作写前提/顺序/预期/失败/停止；证据固定本次输入/版本/命令/结果。只写适用内容，不按模板强制生成文件。

新内容先找已有所有者；确有独立读取场景、更新周期、复用或证据身份时再拆分。索引和指针可定位同一主题，事实正文只维护一处。

## 每次更新的完整动作

1. 读最新正文和相关真实来源，定位信息所属章节，保留用户及其他session改动。
2. 在对应结构中改写、替换或合并，去掉被替代的当前表述；新增独特内容放到适用章节，不在文末追加补丁、纠正或session总结。
3. 同次更新受影响索引、引用、消费者与必要历史身份；确认需求/架构/合同/权限的实质变化仍按原批准门槛，进度与已证实事实按授权维护。
4. 核对独特有效信息是否完整承接、是否出现同义重复、来源是否仍适用。来源/环境改变时复核受影响主题；无法核实的内容明确待核实，不把日期或哈希当语义正确证明。
5. 完成有价值步骤、出现失败/阻断、决定/范围改变或交接前，更新同一任务记录与证据引用，不另建一份session状态稿。

## 历史与退役

历史保存有独特价值的批准/接受、重大决定、失败、许可、原始输出和恢复关联。有效历史结论整合进对应现行正文后，原件只在追溯/恢复时读取。当前路径不再指向INVALID或已被替代规格来定义要求。

清理前核对独特内容、入链、工具加载、证据清单、许可和恢复。相同字节、低入链、年代久或文件短都不足以判删；没有现行用途且没有独特历史价值的材料列删除候选，不通过归档无限堆积。

原始执行与批准保持当时身份；新尝试或纠正单独绑定，不回写历史失败为成功。优先复用已存在的Git历史；本项目的实际工程准备状态见当前任务。非Git时只保留有实际恢复价值的基线，不为每次措辞微调复制整套目录。

## 完成条件

每份现行文档都有必要性、唯一归属和实际读取用途；受影响内容完整、一致、有效、可定位；旧消费者已更新。新session可从索引取得当前上下文，按任务查源码，日常无需翻历史拼需求。

自动检查只能证明其实际覆盖的结构、引用和依赖条件。语义重复、完整性与事实适用性另行核对；没有证据就报告缺口。旧节选hook只覆盖旧试点副本。当前实际入口未接通统一强制门禁；每次修改仍需执行适用检查并记录真实范围，不把试点通过沿用为本项目全路径保障。
