# 验证、诊断与执行边界

用途：设计检查、解释失败、判断证据能支持什么，以及准备真实数据/写操作任务。本文拥有验证方法和容易误判的边界；具体预期、当前结果和产品约束分别由[验收](第1步验收.md)、[当前工作](当前工作.md)、[产品需求](产品需求.md)维护。

## 把证明对象分开

| 层次 | 实际观察 | 不能据此推出 |
|---|---|---|
| 确定性业务检查 | 独立输入、计算/数据结果、错误和副作用 | 模型会选对工具或正确解读结果 |
| 配置/静态引用 | 实际消费者能否解析、符号与引用是否存在 | 工具Schema有效、依赖可用、权限或执行成功 |
| 受控替身/集成 | 指定响应下真实SDK/控制/保存路径的行为 | 真实模型质量、随机行为或整个产品已接通 |
| 真实模型与工具 | 所选工具、参数、执行返回、最终回答分别取证 | 另一模型、版本、输入、长期运行都已通过 |
| 页面与操作 | 实际显示、重载、停止、失败/等待及同源关联 | 后端未验证能力已经实现 |
| 评分器 | 对独立已知正确/错误、边界与反例的判断 | 一个关键词命中就是业务正确；评分器绝对可信 |

例如模型提出get_ticket_stats调用，只证明提出了请求；真实工具返回后，还要核对最终答案是否误读计数和引用。当前轻量eval实际规则直接读[evaluation.py](../../foundation/evaluation.py)，不要把配置字段转述成完整正确性证明。

## 独立预期与失败定位

期望来自用户确认、实际资料和独立业务计算。分别诊断数据、业务逻辑、工具Schema、指令、路由、状态、权限、Provider与测试设计；确认根因需要对应证据，避免把CPU、内存、框架或模型当默认解释。

一次实际检查记录对象与身份、输入/数据、环境、命令/操作、退出状态、输出/差异、逐项PASS/FAIL/UNKNOWN/N/A及限制。构造故障、实际运行与未执行明确区分。旧失败不能被新报告改成成功；再次运行产生新尝试。实际模型返回的内部推理不为补全Trace而事后编造。

改动后核对消费者与受影响案例；费用/耗时/质量按真实任务选指标与取舍，不编造统一绝对阈值。空集、工具失败、评分失败、保存未知不能平均成一个通过率。具体业务正确性、风险和释放条件需要任务独立定义。

## 控制要落到实际执行路径

Prompt表达期望，无法独立保证权限、算术或副作用。业务层和可信执行边界须承担相应硬约束；是否真的拒绝/停止要观察实际路径。模块白名单只是加载约束，虚拟环境和Git worktree均不是沙箱；模板目录或可用SDK不等于接入完成。

人工审批要区分提议、批准、拒绝、取消、实际执行和结果未知。CLI交互本身不构成用户身份/租户授权。外部写入需按真实场景设计权限、审批归属、幂等与审计，拒绝路径检查实际没有副作用，不在测试里暗中批准。

只对确认可安全重试的操作设计有限重试；写入已执行但响应丢失时先查真实状态，避免重复发送/扣款/创建。取消或失败后核对进程、监听、已生成文件及外部资源，无法确认清理则保留UNKNOWN，不能只看主程序退出。

上下文、进程内会话、跨进程恢复与长期Memory分别判断。重启后有聊天记录不证明检查点可恢复；错误记忆和删除要求需要明确来源、作用域与真实消费者。相关产品对象见[完整需求](产品需求.md)。

## 练习与后续风险审查

在获准隔离输入上，可以检查：计数被改错时独立期望是否失败；草稿被说成已提交时是否被识别；空数据是否编出排名；批准/拒绝是否绑定同一对象；固定案例比较时是否把旧模型结果当新模型证明。

接入真实客户或多人生产前，按实际任务审查认证/租户数据权限、凭据保管、持久化审批、幂等、审计、敏感数据记录/删除、成本/时限、告警、回退与运维归属。这里只说明应如何判断，不宣称这些能力已实现或要求当前本地阶段一次全部建设。
